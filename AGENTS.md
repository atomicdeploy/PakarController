Inspect every matching mapping/pending action, then read actual donor sources/dependencies before replacement code or declaring unavailable. Update the existing hash-bound file ledger and GitHub issue with every useful omission; screened/unread files are never accepted exclusions. Add an index route when a failure has no match. Build/stage/capture gates are mandatory and must not be bypassed by direct commands.

- Preserve existing user/concurrent changes. Donor checkouts remain read-only unless the user requests changes there.
- Capability regexes are NOT exhaustive inventory. Consult donor-audit (optionally -Origin / literal -SourcePath) too; inspect AuditOnly, omissions and remaining actions. Keep the existing authoritative ledger, receipt and owning issue synchronized. - Use hostname-first device access. A build, loopback fixture or screenshot is not physical acceptance.
- For screenshots use the built-in framebuffer command or tools/capture-window-windows.ps1 with an explicit verified ExpectedProcessId. The tool imports Pealayer's read-only Win32 capture and automatically falls back when the expected owner cannot provide internal capture. Do not declare Windows screenshots unavailable merely because the external WGC helper failed.
- Never guess a target, accept a blank image or overwrite evidence. Wait for the app's screenshot result, verify PID/backend and inspect the image. IPC acceptance is not capture completion.
- Win32 capture does not focus, move, resize or inject input. Use supported computer-use APIs for desktop input; capture availability does not broaden UI authority.
- Fixtures require an isolated PAKAR_CONFIG_FILE and explicit simulated peer. PAKAR_SCREENSHOT_PATH enables startup capture; with single_instance=false the harness skips production IPC/tray/Jump List hooks and window activation. Stop only owned identity-verified fixtures.

- Low-write builds: use tools/build-desktop.ps1 (Check by default, Test for changed native behavior, Release only when deploying) and its single desktop/target cache. Debug/test symbols are off by default; do not toggle profile/flags/dependency versions gratuitously, build the donor, create extra worktrees/caches, or repeatedly cargo clean. Respect free-space/cache-budget guards; inspect oversized caches instead of deleting shared SDKs.
- Build only affected components. Native UI changes do not require firmware/APK builds. Firmware scripts reuse board/link-mode build paths; -Clean / --clean is troubleshooting-only. Preserve warm release/toolchain caches.
- Current user policy: defer repeated local test suites on incremental passes until completion or significant progress. Routine Check/Test share the release profile/cache; use -DebugArtifacts only for essential diagnostics. For mobile compile-only iteration use build-mobile.ps1 -Mode ApkPreview -BuildOnly, not a second cache or clean. Record deferred verification honestly; do not disable CI acceptance.

Never automate PIN/password/pattern entry, guess lock state or restart the shared ADB server. -Launch and an absolute, nonexisting -Screenshot path provide bounded foreground/capture evidence.

Keep receipts/screenshots small and separate; do not clone entire packages into every feature folder.
